# スマホ小銭研究所 収益ページ雛形 v42.4

このドキュメントは、クレカ・口座開設・スマホ回線・ポイ活の収益ページを増やす前に、ページ構造と誘導を崩さないための設計書です。

目的は、説明を増やすことではありません。  
**少ない情報で判断させ、条件確認を通して、自然に収益リンクへ進ませること**です。

---

## 1. 基本思想

スマホ小銭研究所の収益ページは、長文の比較記事ではなく、**申し込み前の判断導線**として作ります。

基本の流れ：

```text
今のあなたならこれ
↓
条件だけ確認
↓
合うなら申し込み
↓
合わないなら別候補
```

読者に見せる情報は、以下の3層に分けます。

| 層 | 役割 | ページ上の扱い |
|---|---|---|
| 1層目 | どれを選ぶか | ファーストビュー・主役3件・主CTA |
| 2層目 | 合う/合わない判断 | 向いている人・注意点・短い比較 |
| 3層目 | SEO/信頼補足 | 対象外・付与時期・詳しい条件・FAQ |

1層目に細かい説明を詰め込まない。  
詳細は下に逃がし、上部は誘導を太くします。

## 2. ページ種別ごとの役割

### カテゴリ一覧ページ

例：

- `/credit-card/`
- `/mobile-sim/`
- `/account-opening/`
- `/point-site/`

役割：**迷っている読者を、最初に見る候補へ振り分ける。**

やること：

- 主役候補を3件までに絞る
- 目的別の行リンクで補助する
- 比較表は短くする
- 個別ページへ送る

やらないこと：

- 全候補をカードで大きく並べる
- 長文SEO記事にする
- 金額だけで煽る
- いきなり外部ASPリンクへ飛ばす

---

### 個別案件ページ

例：

- `/credit-card/rakuten-card/`
- `/credit-card/epos-card/`
- `/mobile-sim/rakuten-mobile/`
- `/point-site/moppy/`

役割：**申し込み前に合う/合わないを判断し、条件確認後に収益リンクへ進ませる。**

やること：

- 誰向けかを先に示す
- 向いている人/向かない人を短く出す
- 条件チェック後にCTAを置く
- 合わない人向けの別候補を用意する
- PR/アフィリエイト表記を隠さない

やらないこと：

- 公式情報を長々と丸写しする
- すべての細かい条件を上部に詰める
- CTAをページ内に乱立させる
- 「絶対お得」「今すぐ」系の煽りに寄せる

---

### SEOサポート記事

例：

- `楽天カード 入会特典 条件`
- `エポスカード 審査 不安`
- `三井住友カードNL タッチ決済 条件`
- `モッピー 反映されない`
- `楽天モバイル 紹介 条件`

役割：**検索流入の疑問を解消し、個別案件ページへ送る。**

基本導線：

```text
検索流入記事
↓
不安・疑問を解消
↓
個別案件ページ
↓
ASP/紹介リンク
```

SEO記事から直接外部リンクへ飛ばしすぎない。  
まず個別案件ページへ回して、サイト内の収益導線を太くします。

## 3. カテゴリ一覧ページの最小構成

カテゴリ一覧ページは、以下の順番を基本にします。

```text
01. HERO
02. 主役3件
03. 目的別の行リンク
04. 短い比較
05. 条件が合う人向け候補
06. 申し込み前メモ
07. 関連ページ
08. PR表記
```

### 01. HERO

目的：何のページか、誰が次に何を見ればいいかを即理解させる。

出すもの：

- ページ名
- 一言の判断軸
- 主役3件への導入

例：

```text
クレカは、最初の1枚を間違えない。

楽天を使うなら楽天カード。
年会費無料で始めるならエポスカード。
コンビニ・飲食店で使うなら三井住友カード（NL）。
```

### 02. 主役3件

UI：Pick Card  
数：原則3件まで

目的：最初に選ばせたい候補だけを大きく見せる。

クレカなら：

| 候補 | 役割 |
|---|---|
| 楽天カード | 楽天系を使う人向け |
| エポスカード | 年会費無料で始めたい人向け |
| 三井住友カード（NL） | コンビニ・飲食店で使う人向け |

4件目以降はカードにしない。  
条件が合う人向け候補として、下段のリストに逃がします。

### 03. 目的別の行リンク

UI：Row Link  
目的：カードより軽く、迷っている人を振り分ける。

例：

```text
楽天市場・楽天ペイを使う → 楽天カード
年会費無料から始めたい → エポスカード
コンビニ・飲食店で使いたい → 三井住友カード（NL）
ドコモ系サービスを使う → dカード GOLD U
```

### 04. 短い比較

UI：軽い表またはコンパクトリスト  
列数：最大4列

推奨列：

```text
候補 / 向いている人 / 確認する条件 / 進む
```

比較表で全部説明しない。  
詳細は個別ページへ送る。

### 05. 条件が合う人向け候補

主役ではないが、条件が合えば収益性がある候補を置く場所。

例：

```text
dカード GOLD U：ドコモ系・年齢条件が合う人向け
```

UIはコンパクトリスト。  
主役カードと同じ重さにしない。

---

## 4. 個別案件ページの最小構成

個別案件ページは、以下の順番を基本にします。

```text
01. HERO
02. 向いている人 / 向かない人
03. 申し込み前チェック
04. 主CTA
05. 合わない人向けの別候補
06. 条件・対象外・付与時期の補足
07. 関連ページ
08. PR表記
```

### 01. HERO

目的：誰向けかを一瞬で伝える。

例：

```text
楽天カードは、楽天系を使う人向け。

楽天市場・楽天ペイ・楽天モバイルを使うなら、最初に確認したい定番カードです。
入会特典は時期や条件で変わるため、申し込み前に条件だけ確認します。
```

### 02. 向いている人 / 向かない人

UI：Fit Block  
カードにしてもよいが、ページ内で重くしすぎない。

例：

```text
向いている人
- 楽天市場を使う
- 楽天ペイを使う
- 年会費無料のカードから始めたい

向かない人
- 楽天系をほとんど使わない
- 特典条件を確認するのが面倒
- すでに楽天カードを持っている
```

「向かない人」を書くことで、押し売り感を減らします。

### 03. 申し込み前チェック

UI：Check List  
目的：CTA前の納得感を作る。

例：

```text
□ 年会費を確認した
□ 入会特典の条件を確認した
□ いつまでに利用が必要か確認した
□ ポイント付与時期を確認した
□ すでに同じカードを持っていないか確認した
```

### 04. 主CTA

UI：CTA Panel  
目的：収益リンクへ進ませる。

CTA文言：

```text
条件を確認して申し込む
公式キャンペーンを確認する
特典条件を見てから進む
```

避ける文言：

```text
今すぐ申し込む！
絶対お得！
最大◯万円！
知らないと損！
```

### 05. 合わない人向けの別候補

目的：離脱を減らし、内部回遊を作る。

例：

```text
楽天カードが合わない人は
- 年会費無料で無難に始めたい → エポスカード
- コンビニ・飲食店で使いたい → 三井住友カード（NL）
- ドコモ系を使う → dカード GOLD U
```

## 5. カードUIの使用ルール

カードUIは、使いすぎると全部が同じ重さに見えます。  
そのため、カードは「選択」「比較」「行動」に絞ります。

### カードにするもの

- 最初に選ばせたい主役候補
- 申し込み前の重要判断
- 条件チェック
- 主CTAパネル

### カードにしないもの

- 通常の説明文
- PR表記
- 関連リンクの羅列
- 軽い注意書き
- すべての補足メモ
- セクションごとのただの囲み

### 1画面内のカード数

- 主役カードは原則3枚まで
- 4件目以降はコンパクトリストにする
- 同じ見た目のカードを連続させすぎない
- カードの連打で「どれが主役か」を消さない

UIの重さは以下で分けます。

| 役割 | UI | 重さ |
|---|---|---:|
| 主役候補 | Pick Card | 高 |
| 目的別導線 | Row Link | 中 |
| 比較 | Table/List | 中 |
| 注意/補足 | Note | 低 |
| PR表記 | Small Note | 低 |
| 関連リンク | Text Link | 低 |
| 主CTA | CTA Panel | 高 |

## 6. 収益リンク設置ルール

収益ページには、必ず主収益リンクを定義します。

| 種別 | 主な収益リンク | 備考 |
|---|---|---|
| クレカ | ASP / 楽天アフィリエイト | 個別ページで条件確認後にCTA |
| 口座開設 | アクセストレード等ASP | 審査中は広告リンクを無理に置かない |
| スマホ回線 | A8 / 楽天アフィリエイト / 公式ASP | 料金・キャンペーン条件を確認後にCTA |
| ポイ活 | 友達紹介リンク | 低単価なので高単価カテゴリへの横導線も置く |
| TikTok Lite | 招待リンク | 集客入口。単体に寄せすぎない |

### 1ページ1主CTA

1ページ内の主CTAは、原則1種類に絞ります。  
複数の外部リンクを並べる場合でも、主導線と補助導線を分けます。

例：

```text
主CTA：条件を確認して申し込む
補助：合わない人は別候補を見る
```

## 7. SEOと収益導線の接続

マネーページだけでSEOを取りにいかない。  
検索流入用の記事と、収益用ページを分けます。

```text
SEOサポート記事
↓
個別案件ページ
↓
条件確認
↓
ASP/紹介リンク
```

狙いやすいキーワード：

```text
条件
対象外
反映されない
付与時期
申し込み前
失敗
審査 不安
キャンペーン 条件
```

スマホ小銭研究所は、煽りではなく「失敗しないための確認」で取る。

## 10. 公開前の収益ページチェック

収益ページを公開する前に、以下を確認します。

```text
1. このページの主収益リンクは何か
2. クリック先はASP/紹介/楽天アフィリエイトのどれか
3. PR表記はあるか
4. 条件確認後にCTAが出ているか
5. 合わない人向けの代替候補があるか
6. 内部リンクで回遊できるか
7. sitemapに入っているか
8. titleに検索意図が入っているか
9. meta descriptionがあるか
10. 公式条件確認を促しているか
11. カードUIを使いすぎていないか
12. ファーストビューに説明を詰め込みすぎていないか
```

---

## 11. やらないこと

- 説明を増やして安心感を作ろうとしない
- カードUIを全セクションに使わない
- 主CTAを複数色・複数文言で乱立させない
- 未完成カテゴリを主役にしない
- 口座審査中に無理なランキングを作らない
- SEOのためにページ上部を長文化しない
- 金額だけで煽らない
- 読者に「結局どれ？」と思わせない

サイト全体の収益導線は、以下を基本にします。

```text

↓
主役3件
↓
個別案件ページ
↓
条件確認
↓

```

SEO導線：

```text

↓
個別案件ページ
↓

```


## 13. 公開ページでは全部見せない

このドキュメントは内部設計用です。  
公開ページでは、ここに書いた要素をすべて同じ重さで表示しません。

上部に出すのは以下だけです。

- 何のページか
- 最初に見る主役3件
- 条件を見るCTA

目的別導線・比較・注意点・PR表記・関連リンクは、必要に応じて下部に置きます。  
読者が最初の画面で迷う場合は、要素を足すのではなく削ります。

### 公開ページの上部制限

- 主役カードは3件まで
- ファーストビューの説明は2〜3行まで
- CTA文言は1種類に絞る
- 比較表は上部に置かない
- 補足メモをカード化しない
- 関連リンクを上部に置かない
- 1画面内で判断軸を増やしすぎない

### 判断基準

ページを見た読者が、最初の10秒で次のどれかを選べない場合は情報過多です。

```text
楽天系を使う → 楽天カードを見る
年会費無料で始める → エポスカードを見る
コンビニ・飲食店で使う → 三井住友カード（NL）を見る
```

迷う場合は説明を追加するのではなく、選択肢・カード・補足を削ります。

## 収益リンクの実装

承認済みASP案件は`data/monetization/programs.json`で一元管理します。
個別ページは`cta.program_id`で参照し、URL・PR注記・計測ピクセルを複製しません。
一覧ページからASPへ直接送らず、個別の条件確認ページを経由します。

クレジットカード領域は以下で生成します。

```text
data/credit-card/*.json
data/credit-card-hub.json
templates/credit-card-detail.html
templates/credit-card-hub.html
assets/kozeni-credit-card.v1.css
tools/build_credit_cards.py
```

```bash
python3 tools/build_credit_cards.py
python3 tools/build_credit_cards.py --check
```
